# Idea backlog

Every idea and owner note worth keeping, with an honest assessment, so Ken, Alyssa and their AIs can discuss them. **Nothing here is approved or scheduled until a human says so.** `HANDOFF.md` holds current state; `chat/agenda.md` is the discussion list for the AIs. Add new ideas here; when one ships, mark it done rather than deleting it.

Ratings: **Value** (for the mission: beginners who can really get around Japan, through a game people enjoy) High, Medium or Low. **Effort** S (hours), M (days), L (a week or more). "Cause" lines say what was seen in the code; anything not checked says so.

## Decisions made (Ken, 2026-11-01)

Alyssa hasn't weighed in yet; Dojo matters stay hers.

1. **The Path waits.** No more Path art until it has a system (1.1). Don't run `argon-outbox/kotodama-path-scenes.zip`. **Content and lessons are the last focus,** after the rest of the app is built, functional and polished, so the Path system and full kana content come late too.
2. **The town isn't fully Edo.** The station, onsen and other modern places stay because they're useful for real travel. A **modern and a past-day town** can coexist, with an extra town given later on, like the Builder Base in Clash of Clans. **The modern town comes first;** the historical guide (3.5) goes in the past-day town, as a reward. **Towns are islands** (Ken has reference photos; they still need to be added to the repo): tapping a building zooms into it and opens the worker assignment UI in place, with fluid animation and modeling. This reshapes the current flat `TownMap` and bottom sheet when the town work comes up. Performance caution: zoom a single flattened layer, not many animated SVGs.
3. **The server may make designs, as a test.** The Argon-only rule existed because Argon was judged the best designer hands down; testing whether the server can do better is within that intent. See section 4. **Ken wants rules applied by their intent:** "We're co-developers", so an AI should override one of his decisions, and say so, when the reason behind it has changed.
4. **Koto's desk replaces the page titles on desk pages.** "The desk" means the whole framed stage of Koto's UI (as mayor in the Town, with his mustache in the Shop). Its current size is good. It **doesn't appear on the full-screen Path,** which is like the Dojo: the design is the screen. The Town map's treatment follows the same logic where it's full screen.
5. **Characters change art style per area, for now** (tentative: "Sure, why not for now?"). This multiplies art: each character and outfit would need up to three styles, so prove it on one character before committing (2.1).

### 4. The AI server

**Concern:** "I don't see the designs and worry about how you used the server. If it is only provably able to copy a reference, it's not going to be an incredibly useful asset."

**Ken's concern is correct.** So far:

- It has run Hunyuan3D 2, which turns one drawing into an untextured 3D shape. Nothing from it is in the game.
- The overnight test scored how closely each shape's silhouette matched the drawing. **That metric rewards copying,** so a high score says nothing about creating anything new. "Good for reference shapes" is the most it supports.
- Results are in `design/reference/server3d/iter/` (`viewer.html`); the models are git-ignored and local to Ken's PC.

**What copying is still good for (narrowly):** turnarounds. A 3D shape of an existing character gives Argon consistent back and side views and walk poses, which is what the avatar work (2.1, 2.3) keeps struggling with.

**What it would take to create:** Hunyuan3D can't invent, so the server would need an image or text-to-3D model to make new concepts. Whether one runs on this ARM machine alongside his dad's vLLM is unverified, and nothing should be installed without asking.

**One-night test (approved in principle by Decision 3; installing anything on the server still needs a go-ahead):** prompts for 3 characters that don't exist yet (say, a new Bamboo Thicket yokai), about 20 results each, rated blind by Ken and Alyssa against Argon's take on the same prompts. Success = several results they'd really build on. If it fails, stop and use the server only for turnarounds. Also useful and lower risk: its Qwen model could draft lesson content or Town guide entries overnight for checking, if his dad's OK with that.

## Suggested order

Updated for Ken's decisions: the app comes first; content, lessons and the Path come last.

1. **Quick fixes, no new art:** blush (2.2), spacing and headline (2.6), floating houses (2.5), opt-in vocabulary (3.2), review Dojo stops walking (2.7, with Alyssa).
2. **The app shell:** fluid pages (1.3), frame rate (1.4), Koto's desk and transitions (1.2).
3. **Server creation test** (section 4), so its result can feed the art below.
4. **Game systems:** mastery levels and "Which icon?" (3.1), Shop speaking (3.3), Town resources and the second town (3.5), test-out (3.4), Dojo work (Alyssa).
5. **Character art:** one character in each area's style first, then the avatar (2.1), walk cycles (2.3) and spirits (2.4).
6. **Last:** the Path system (1.1), then full lessons and kana content.
